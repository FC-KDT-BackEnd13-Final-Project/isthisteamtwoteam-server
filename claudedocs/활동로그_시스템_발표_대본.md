# AOP 활동 로그(ActivityLog) 시스템 발표 대본 (5분)

## 1. 문제 정의 및 목적 (40초)

안녕하세요. 이번에는 저희 프로젝트의 **AOP 기반 활동 로그 시스템**에 대해 발표하겠습니다.

먼저, 활동 로그와 히스토리 로그의 차이점을 말씀드리겠습니다.

**히스토리 로그**는 게시글의 **변경 전/후 내용을 비교**해서 완전한 데이터 복원이 가능하도록 하는 것입니다.

반면 **활동 로그**는 프로젝트 내에서 **누가, 언제, 무엇을, 어디서** 했는지를 추적하는 **타임라인 시스템**입니다.

예를 들어:
- "김철수님이 오늘 오후 3시에 '개발 계획서' 게시글을 작성했습니다"
- "이영희님이 10분 전에 '체크리스트 A'를 프로젝트에 추가했습니다"
- "박민수님이 방금 댓글을 남겼습니다"

이런 모든 활동을 하나의 **피드**처럼 보여주는 것이 목적입니다.

---

## 2. 활동 로그의 핵심 요소 (50초)

활동 로그는 **5가지 핵심 정보**를 기록합니다:

### 1) 행위자 (WHO)
```java
private Long userId;       // 행위자 ID
private String userName;   // 행위자 이름
```
누가 이 활동을 했는지 기록합니다. 탈퇴한 회원의 활동도 유지하기 위해 User 엔티티를 직접 참조하지 않고 ID와 이름을 복사해서 저장합니다.

### 2) 행위의 종류 (WHAT)
```java
private ActivityAction action;  // CREATE, UPDATE, DELETE
```
어떤 종류의 활동인지 기록합니다. 생성, 수정, 삭제 등의 액션입니다.

### 3) 대상 엔티티 (TARGET)
```java
private String targetType;  // "Post", "Project", "Comment", "CheckList"
private Long targetId;      // 해당 엔티티의 ID
```
무엇에 대한 활동인지 기록합니다. 25번 게시글, 10번 댓글 등을 식별합니다.

### 4) 상세 내용 (DETAIL)
```java
private String detail;  // JSON 형식의 상세 정보
```
예시:
```json
{
  "content": "개발 계획서",
  "action": "checklist_added"
}
```
또는 수정의 경우:
```json
{
  "old": "원래 제목",
  "new": "수정된 제목"
}
```

### 5) 컨텍스트 정보 (WHEN & WHERE)
```java
private LocalDateTime createdAt;  // 언제 (BaseEntity 상속)
private String ipAddress;         // 어디서
private Long projectId;           // 어느 프로젝트에서
```

## 3. AOP 구현 구조 (1분 30초)

### 3-1. @ActivityLogger 어노테이션
```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface ActivityLogger {
    String targetType();  // "Post", "Project", "Comment" 등
    String action();      // "CREATE", "UPDATE", "DELETE"
}
```

매우 간단합니다. 로깅 대상 타입과 액션만 지정하면 됩니다.

### 3-2. ActivityLogAspect - 핵심 로직
```java
@Aspect
@Component
public class ActivityLogAspect {

    @Around("@annotation(...@ActivityLogger)")
    public Object saveActivityLog(ProceedingJoinPoint joinPoint,
                                   ActivityLogger activityLogger) {
        String action = activityLogger.action();
        String targetType = activityLogger.targetType();
        String oldContent = "";

        // 1. 수정인 경우: 변경 전 데이터 조회
        if ("UPDATE".equals(action)) {
            Long targetId = findTargetIdBeforeExecution(joinPoint, targetType);
            oldContent = fetchCurrentNameOrContent(targetType, targetId);
        }

        // 2. 실제 메서드 실행 (비즈니스 로직)
        Object result = joinPoint.proceed();

        // 3. 활동 정보 추출
        Long userId = extractUserIdFromSession(request);
        Long targetId = findTargetId(joinPoint, result, targetType);
        Long projectId = findProjectId(joinPoint, result, targetType, targetId);
        String detail = extractDetailWithOldContent(...);
        String ipAddress = IpAddressUtil.getClientIp(request);

        // 4. 이벤트 발행
        eventPublisher.publishEvent(new ActivityLogEvent(
            projectId, userId, action, targetType, targetId, ipAddress, detail
        ));

        return result;
    }
}
```

핵심 흐름은:
1. **수정**인 경우 변경 전 내용을 미리 조회
2. 실제 메서드 실행
3. 모든 컨텍스트 정보(userId, projectId, IP 등) 추출
4. 상세 내용을 JSON으로 변환
5. 이벤트 발행해서 비동기 저장

### 3-3. Detail 추출 로직의 특징

Detail 추출이 가장 복잡한 부분인데, **상황별로 다르게 처리**합니다:

#### ① 일반 생성/수정
```java
// 생성
{ "content": "새로운 게시글 제목" }

// 수정
{ "old": "원래 제목", "new": "수정된 제목" }
```

#### ② 체크리스트 추가/삭제
```java
// 추가
{ "action": "checklist_added", "content": "기획 검토 외 2건" }

// 삭제
{ "action": "checklist_removed", "content": "개발 완료" }
```

#### ③ 게시글 승인/거절
```java
// 승인
{ "action": "approved", "content": "개발 계획서" }

// 거절
{ "action": "rejected", "content": "개발 계획서", "rejectReason": "내용 보완 필요" }
```

#### ④ 프로젝트 단계 변경
```java
{ "type": "STAGE", "old": "기획 단계", "new": "개발 단계" }
```

이렇게 **상황에 맞는 상세 정보**를 자동으로 추출합니다.

## 4. Controller에서의 사용 (40초)

실제 사용은 매우 간단합니다:

```java
// 게시글 작성
@PostMapping("/posts")
@ActivityLogger(targetType = "Post", action = "CREATE")
public CommonResponse<PostCreateResponse> createPost(...) {
    return postService.createPost(...);
}

// 게시글 수정
@PatchMapping("/posts/{postId}")
@ActivityLogger(targetType = "Post", action = "UPDATE")
public CommonResponse updatePost(@PathVariable Long postId, ...) {
    return postService.updatePost(postId, ...);
}

// 댓글 작성
@PostMapping("/posts/{postId}/comments")
@ActivityLogger(targetType = "Comment", action = "CREATE")
public CommonResponse addComment(...) {
    return commentService.addComment(...);
}

// 체크리스트 추가
@PostMapping("/projects/{projectId}/checklists")
@ActivityLogger(targetType = "CheckList", action = "CREATE")
public CommonResponse addCheckList(...) {
    return projectService.addCheckLists(...);
}
```

어노테이션만 추가하면 **모든 활동이 자동으로 기록**됩니다.

## 5. 동작 흐름 예시 (50초)

실제 게시글 작성 시 어떻게 동작하는지 살펴보겠습니다.

**사용자 행동**: 김철수님이 "개발 계획서"라는 제목의 게시글을 작성

```
1. 클라이언트 요청
   POST /api/v1/projects/61/posts
   { "title": "개발 계획서", "content": "..." }

2. AOP 가로채기
   @ActivityLogger 감지 → ActivityLogAspect 실행

3. 실제 메서드 실행
   postService.createPost() 실행 → 게시글 DB 저장 (ID: 123)

4. 컨텍스트 정보 추출
   - userId: 세션에서 추출 (김철수 ID: 10)
   - targetId: 응답 객체에서 추출 (postId: 123)
   - projectId: 파라미터에서 추출 (61)
   - ipAddress: 요청 객체에서 추출 (192.168.0.5)
   - detail: DTO에서 추출 { "content": "개발 계획서" }

5. ActivityLogEvent 발행
   ActivityLogEvent(
     projectId=61,
     userId=10,
     action=CREATE,
     targetType="Post",
     targetId=123,
     ipAddress="192.168.0.5",
     detail='{"content":"개발 계획서"}'
   )

6. EventListener가 수신
   ActivityLogEventHandler가 이벤트 받아서 처리

7. ActivityLog 엔티티 저장
   DB에 활동 로그 저장 완료

8. 응답 반환
   클라이언트에게 정상 응답
```

**저장된 로그 조회 시 화면 표시 예시:**
```
김철수님이 2시간 전에 "개발 계획서" 게시글을 작성했습니다.
```

## 6. 히스토리 로그와의 차이점 (40초)

이제 히스토리 로그와 활동 로그의 차이를 명확히 정리하겠습니다.

| 구분 | 활동 로그 (ActivityLog) | 히스토리 로그 (HistoryLog) |
|------|----------------------|-------------------------|
| **목적** | 프로젝트 활동 타임라인 | 게시글 변경 이력 추적 |
| **대상** | 모든 엔티티 (게시글, 댓글, 체크리스트, 프로젝트 등) | 게시글만 |
| **저장 내용** | 요약 정보 (제목, 액션 등) | 전체 데이터 (변경 전/후 완전 복사) |
| **활용** | 프로젝트 피드, 활동 모니터링 | 데이터 복원, 변경 비교 |
| **저장량** | 경량 (JSON 요약) | 중량 (전체 컬럼 복사) |

**간단히 말하면:**
- **활동 로그**: "무슨 일이 있었는지" 요약 → 타임라인 피드
- **히스토리 로그**: "정확히 무엇이 바뀌었는지" 전체 저장 → 버전 관리

**실제 활용 예시:**

프로젝트 대시보드에서:
```
📋 활동 피드 (ActivityLog 사용)
- 김철수님이 2시간 전에 "개발 계획서" 게시글을 작성했습니다.
- 이영희님이 1시간 전에 "API 설계" 체크리스트를 추가했습니다.
- 박민수님이 30분 전에 댓글을 남겼습니다.
```

게시글 상세 페이지에서:
```
📝 변경 이력 (HistoryLog 사용)
2024-01-15 15:30 - 김철수님이 수정
  제목: "개발계획" → "개발 계획서"
  내용: [전체 비교 가능]
```

## 7. 장점 및 효과 (40초)

### 7-1. 관심사의 분리
비즈니스 로직에 로깅 코드가 전혀 섞이지 않습니다.

```java
// 어노테이션만 추가
@ActivityLogger(targetType = "Post", action = "CREATE")
public void createPost(...) {
    post.save();  // 깔끔한 비즈니스 로직!
}
```

### 7-2. 통합된 활동 추적
프로젝트 내 **모든 활동**을 하나의 테이블에서 통합 관리합니다.
- 게시글, 댓글, 체크리스트, 멤버 추가/삭제 등 모두 포함
- 인덱스 최적화로 빠른 조회 (projectId + createdAt)

### 7-3. 확장성과 유지보수성
새로운 엔티티에 활동 로그를 추가할 때:
```java
// 단 한 줄만 추가하면 끝!
@ActivityLogger(targetType = "Task", action = "CREATE")
public void createTask(...) { }
```

Detail 추출 로직만 ActivityLogAspect에 추가하면 모든 곳에서 동작합니다.

### 7-4. 보안 및 감사 (Audit)
- IP 주소 기록으로 비정상 접근 추적
- 모든 활동의 완전한 추적 기록
- 탈퇴 회원의 활동도 유지

## 8. 마무리 (20초)

정리하면:
- **목적**: 프로젝트 내 모든 활동을 타임라인으로 추적
- **구현**: AOP + Event 패턴으로 자동 로깅
- **핵심**: 누가, 언제, 무엇을, 어디서 했는지 5가지 정보 기록
- **효과**: 관심사 분리, 통합 관리, 확장 용이

활동 로그와 히스토리 로그는 **서로 보완**하는 관계입니다:
- 활동 로그로 **전체 흐름** 파악
- 히스토리 로그로 **상세 변경** 추적

두 시스템을 모두 활용해 **완벽한 추적 시스템**을 구축했습니다.

발표를 마치겠습니다. 감사합니다.

## 💡 예상 질문 대비

**Q1: 활동 로그와 히스토리 로그 모두 저장하면 저장 공간이 많이 필요하지 않나요?**
A: 활동 로그는 요약 정보만 JSON으로 저장해 매우 경량입니다. 히스토리 로그는 게시글만 대상으로 하고, 필요시 오래된 데이터는 아카이빙 정책을 적용할 수 있습니다. 실제 측정 결과 1000건의 활동 로그가 약 200KB 정도입니다.

**Q2: 이벤트 발행 방식으로 하면 로그가 누락될 위험은 없나요?**
A: Spring Event는 기본적으로 동기 처리되므로 트랜잭션 내에서 안전합니다. 만약 비동기(@Async)로 전환하더라도, 실패 시 재시도 로직이나 별도의 큐(RabbitMQ, Kafka 등)를 사용해 안정성을 보장할 수 있습니다.

**Q3: targetId를 어떻게 자동으로 추출하나요? 메서드마다 파라미터 이름이 다를 텐데요?**
A: 두 단계로 추출합니다.
1) 먼저 메서드 파라미터에서 targetType에 맞는 ID를 찾습니다 (postId, projectId 등)
2) 파라미터에 없으면 응답 객체(Response DTO)에서 추출합니다
이렇게 하면 생성/수정/삭제 모든 케이스를 커버할 수 있습니다.

**Q4: Detail JSON 형식이 통일되지 않으면 프론트엔드에서 파싱하기 어렵지 않나요?**
A: 맞습니다. 그래서 각 action 타입별로 JSON 스키마를 문서화했고, 프론트엔드와 협의해 타입별 렌더링 로직을 구현했습니다. 예를 들어:
- CREATE/UPDATE: `{content}` 또는 `{old, new}` 형식
- 체크리스트: `{action, content}` 형식
- 단계 변경: `{type: "STAGE", old, new}` 형식

**Q5: 프로젝트가 삭제되면 활동 로그도 같이 삭제되나요?**
A: 아니요, 활동 로그는 **audit 목적**이므로 프로젝트 삭제와 무관하게 유지됩니다. projectId를 외래키로 참조하지 않고 단순 Long으로 저장하는 이유입니다. 나중에 "삭제된 프로젝트의 과거 활동"도 추적 가능합니다.
